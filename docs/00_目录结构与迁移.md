# 目录结构与迁移

文档和命令统一以项目根目录 `<root>` 为基准。新代码和文档使用相对路径，不写死本机盘符。

## 核心目录（2026-10-19 精简后，只保留实际使用相关内容）

| 路径 | 用途 | 保留策略 |
|---|---|---|
| `production/` | SolarXR 输入、标定、模型调度、录制回放、Unity/Web 输出 | 生产核心 |
| `mobileposer/` | 各模型算法和 SMPL 基础实现；不包含生产主流程 | 模型实现 |
| `runtime/slimevr/SlimeVR-Server/` | SlimeVR 独立程序源码 | 本地权威源 |
| `runtime/unity/SpineRecovery_V2/` | Unity 工程、AvatarScene、PoseSource | 本地权威源 |
| `runtime/android/android_capture_app/` | 手机研究录像客户端 | 与 `production.capture_server` 配套 |
| `solarxr_protocol/` | Python SolarXR FlatBuffers 绑定 | 核心代码 |
| `checkpoints/` | 实时模型权重：`pnp5_60a_s42_ftr3/`（默认）、`pnp5_60a_sc_ftr3/`（恒等锚定） | 保留 |
| `configs/`、`scripts/` | 实时配置、安装脚本与权重转换/验证脚本 | 保留 |
| `recordings/` | 实时录制、回放和报告 | 保留（不入 git） |
| `docs/` | 当前主文档，编号 00–11 | 保留 |

Unity `Library/`、Gradle、pnpm、CMake、Electron 等构建缓存不属于源码，需要时由各自工具链重新生成。

## 独立程序与工作区对应关系

`MotionRecoverWorkspace/` 是唯一的本地工作根。Python、SlimeVR、Unity 和 Android 客户端均以 `runtime/` 下的对应目录为本地权威源；训练数据和大规模生成结果保留在服务器。

`.reorg_check`、`.workbench-stage` 和空的 `local_sample_data/` 已于 2026-11-11 按“以实际使用为准”删除，不属于当前生产或训练路径。

## 项目重命名

若将根目录改为 `motionUse`，代码应继续使用相对路径。Codex 会话通常绑定旧工作区路径；可以在旧路径创建指向新目录的 Windows junction，并在新会话提供 `docs/README.md` 和 `docs/01_项目目标与当前状态.md`。

## 清理规则

- 不删除 checkpoint、SlimeVR 源码、Unity 源码和构建缓存。
- 与实际使用无关的内容先移入存档目录，不直接删除；确认多次无需后再决定是否永久清理。
- 清理前后用 `rg` 检查引用。
- 不覆盖用户已有的未提交修改。
