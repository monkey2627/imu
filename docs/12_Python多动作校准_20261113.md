# Python 多动作手腿校准

入口：运行现有 Python 实时服务，打开它提供的 production viewer，在右侧「动作校准（手与腿）」选择动作，点击「开始 / 重新校准」。每步先有 4 秒准备时间，再保持 6–10 秒；网页显示姿势提示、倒计时与各传感器复核结果。切换选择会取消正在进行的流程，然后可开始另一种动作。

| 选项 / action | 校准与复核姿势 |
|---|---|
| 死虫 / `deadbug` | 仰卧屈膝、双臂平放体侧校准双前臂；桌面式校准双小腿；左右对侧伸展和回到桌面式复核 |
| 臀桥 / `hipthrust` | 仰卧伸腿、双臂平放体侧校准双前臂与双小腿；屈膝准备、抬臀、落臀复核双前臂 |
| 左侧桥 / `sidebridge_left` | 仰卧伸腿校准四肢；左肘支撑准备、抬髋复核双前臂；落髋侧卧伸腿复核双小腿 |
| 右侧桥 / `sidebridge_right` | 同上，左右镜像 |
| 卷腹 / `crunch` | 仰卧伸腿校准四肢；屈膝准备、小幅卷腹双臂向脚端前伸、躺回复核 |
| 卧位猫（四点跪姿猫式）/ `lyingcat` | 四点跪姿校准双小腿；双膝不离地，分别向前伸直左右臂校准前臂；回到双手撑地中立位复核四肢 |

卧位猫的动作定义在当前仓库中未找到，本次明确按四点跪姿猫式设计，网页也标明该定义。左右伸臂是准备校准姿势，不是要求在猫式屈伸时持续伸臂。

鸟狗的现有步骤、命令和求解器均未修改，继续使用原入口。Unity 场景中的旧校准入口也未修改；本次新增流程从 Python 网页选择，避免同时运行两个校准流程。

## 求解与回退

新代码位于 `runtime/python/production/exercise_calibration.py`，复用现有静止窗口搜索与腰部身体坐标计算。每步只搜索保持阶段最近的窗口，寻找肢体和腰都稳定的 0.5 秒；腿陡直时不强行求水平朝向，所以臀桥、卷腹、侧桥先用伸腿准备姿势校准。水平目标同时修正世界朝向和有上限的局部倾斜；倾斜大于 30°时拒绝，复核方向误差超过 25°时失败。不会宣称观测到沿骨轴的扭转，也不从小腿朝向推算真实大腿角度。

每种流程都包含双前臂和双小腿校准。开始时清除旧四肢修正后重新解算，腰部已有修正继续作为身体参考。猫式伸臂以中立位腰部头向为参考，减少伸臂时腰部转动引入的朝向偏差。校准未通过或取消时恢复整套旧朝向/安装修正和原手臂先验开关；只有全部步骤通过才保留新修正。不持久化跨次穿戴的修正缓存。

新流程自动录制校准输入和事件，支持 `production.offline_compare` 重放解算、完成或失败回退。同帧的多个事件按记录顺序处理。侧桥关闭直臂先验，防止把支撑侧屈肘误当成直臂。

WebSocket 命令：

```json
{"command":"exerciseCalibrationStart","action":"deadbug"}
{"command":"exerciseCalibrationCancel"}
```

广播的 `exerciseCalibration` 包含 `action`、`active`、`outcome`、`step`、`total`、`instruction`、`preparing`、`remaining`、`results`。倒计时随有效输入帧推进，输入停止时不会继续采集或宣布成功。

## 验证

从 `runtime/python` 执行：

```powershell
& 'E:/dyh/conda_envs/mobileposer/python.exe' -m analysis.calibration.exercise_calibration_synthetic
& 'E:/dyh/conda_envs/mobileposer/python.exe' -m analysis.calibration.bird_dog_calib_synthetic
```

合成验证覆盖六个选项、两个身体朝向、独立传感器朝向误差（包括前臂 +115° / −70°）、固定安装偏差、噪声、计时完成、动作切换与取消、错误躯干姿势、移动传感器、缺少传感器、关闭校准，以及离线完成/失败回退。网页脚本通过 Node 语法检查；Python 模块通过编译与运行环境导入检查。尚未用真人 IMU 验证，各动作仍需实测校准与复核结果。
