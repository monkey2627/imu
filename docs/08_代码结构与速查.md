# 代码结构与速查（2026-10-19）

`MotionRecoverWorkspace/` 是统一工作根。Python 负责 SlimeVR → Python 实时推理 → Web / Unity；SlimeVR、Unity 和 Android 客户端作为独立工程位于 `runtime/` 下。训练数据和生成产物保留在服务器。

## 1. 数据流

```text
IMU tracker → SlimeVR Server（校准、mounting、reset）→ SolarXR ws://127.0.0.1:21110
→ solarxr_client → layout（5 个 tracker 绑定检查）→ calibration（SlimeVR 帧 → SMPL 骨骼帧）
→ 60 Hz 滑窗(91 帧) → mobile_export.MobilePose（Joints → Poser）→ rotmat → stream_out
→ ws://127.0.0.1:21200 → Unity Avatar / web_visualizer（http://127.0.0.1:8765/）
```

## 3. 速查

**佩戴与绑定**（详见 `01`、`03`）：前臂近腕背侧 → Left/Right lower arm；小腿膝下前内侧 → Left/Right **ankle**（枚举 LOWER_LEG，不是 foot）；骨盆后侧骶骨 → Hip。位置图 `docs/images/sensor_placement_pnp5.png`。

**SlimeVR 校准**：Automatic mounting（Full Reset 站直 → 滑雪姿势 Mounting calibration）；手臂 Reset 模式保持默认 Back。

**启动**：`python -m production.run --model pnp5_60a_s42_ftr3 --web`；`--model pnp5_60a_sc_ftr3` 用锚定版；`--infer-every 1` 为 60 poses/s；`--record <文件>` 录制。

**校准后检查**：`run --record` 站直 5 秒 → `python scripts/check_standing_orientation.py <录制>`。

**实际验证**：启动 SlimeVR、`python -m production.run --web` 和 Unity，按录制/回放流程检查真实输入、模型输出和 Unity 动作。

## 4. 约定与易错点

- feature 顺序：5 个加速度（/30）在前，5 个方向矩阵（9 维）在后；不是按传感器交错。
- 窗口固定 60 Hz 推进；30 Hz 的数据不能喂给这个模型（旧 30 Hz 录制会被 `replay_recording` 拒绝）。
- checkpoint 必须带 `manifest.json`，帧率/窗口/布局/锚定标记不符会直接报错；锚定网络与普通网络输出含义不同，不能混用。
- 骨盆朝向用骨盆骨（关节 0），传感器戴在骶骨后侧；旧的腰前侧 spine1 已废弃。
- 足接触输出已移除（新基线没有接触头）；Unity 把 `footContact` 当可选字段。
- 火柴人视图的骨长是写死的模板，只用来看姿态，不代表真实比例。
