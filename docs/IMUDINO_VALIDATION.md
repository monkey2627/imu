## 已完成

1. 只读检查服务器仓库 README、downstream README、模型、预处理、训练及验证代码，确认仓库没有可直接用于本项目的线上五 IMU 姿态入口。`example_forward.py` 仅为基础编码器样例，`render_validation.py` 依赖缓存与伪标签，未作为在线入口。
2. 读取 `best.pt` 实际字段和权重尺寸；head 与 backbone 均 strict=True 完整加载。两个本地部署文件的 SHA256 与服务器一致，详见 checkpoint 目录的 manifest。
3. 服务器 PyTorch 2.15.0+cu132、timm 1.0.30 上，同一完整编码器权重、480 帧五路随机输入并包含无效末尾 patch：官方 timm 实现与本地兼容算子的编码特征、姿态头输出最大绝对差均为 0。
4. 本地 `mobileposer`：Python 3.9.25、PyTorch 2.1.2+cu121、RTX 4090，无环境升级。GPU/CPU 均成功执行完整编码器、头和根节点求解。CPU 单次约 0.534 秒，静止输入 GPU/CPU 输出矩阵最大绝对差约 1.38e-5。
5. 静止输入比力为 `(0,9.81,0)`，角速度为 0；随机旋转的目标 6D 编码/解码一致；拒绝错误传感器顺序；1 帧启动补齐可推理；输出 `[24,3,3]`，所有旋转有效；`R_root @ R_local[3]` 与腰部方向最大绝对差约 1.19e-7。
6. 实际 `production.run` 入口，读取原有 `BirdDog_RingSkinC_Recorded_20261101_145430.jsonl`（61.6 秒录制），以本机临时端口 21209 启动，用真实 WebSocket 客户端接收 40 帧。全部为 `waist_imudino_fiveimu`，布局正确，每帧 96 个有限四元数分量，24 个四元数均归一化；modelFps=60、lag=0，输出代表帧等于最新输入帧。预热后推理中位耗时 11.71 ms，P95 13.33 ms；首次冷启动 CUDA 推理另测约 3.51 秒。测量值随机器负载变化。
7. 14 个新增或相关 Python 源文件通过内存编译检查，没有新增持久化测试脚本或测试数据。
8. 另一次完整生产入口回放收取 100 帧，输入推进到第 698 帧，已覆盖完整 480 帧真实历史。通过 WebSocket 的 `selectModel` 命令切到 `waist_mobileposer_amass`，再切回 `waist_imudino_fiveimu`；两次均成功，lag 从 0 变为 10 再回到 0，新模型继续输出 96 个四元数分量。

## 验证边界

上述为训练实现一致性、部署契约、已有真实 IMU 录制回放及 WebSocket 协议验证。
未运行新训练、重新生成特征、重写验证集、修改 checkpoint 或重新渲染视频。
未以伪标签提供在线根节点。未用录制回放结果宣称有真实姿态精度指标。

Unity 仅增加菜单项，沿用现有四元数协议。本环境未运行 Unity Editor 编译、构建或穿戴五 IMU 的硬件联调；
交付中没有更新 Unity 已构建可执行文件。实际穿戴时仍需按现有 SlimeVR/Unity 流程校准，检查安装偏差、
动作延迟、根姿态和贴地效果。在线末帧推理与离线重叠融合的区别见部署说明。

验证使用的桥进程在检查结束后已终止，不占用正式 21200 端口。原录制文件和服务器训练文件保持原样。
