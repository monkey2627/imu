# 安装、构建与启动

## Python 环境

使用 `mobileposer` conda 环境运行实时程序（Python ≥ 3.9：代码使用 `asyncio.to_thread`）。

## SlimeVR 本地构建

本机已验证 JDK 17、CMake、pnpm、Visual Studio 2022 C++ x64/x86 和 Windows SDK 10.0.22621.0。

```powershell
.\SlimeVR-Server\scripts\build-windows-local.ps1 -ValidateOnly
.\SlimeVR-Server\scripts\build-windows-local.ps1
```

成功后应用目录为 `SlimeVR-Server\gui\dist\artifacts\win\win-unpacked\`，应包含 `SlimeVR.exe`、`slimevr.jar`、`SlimeVR-Bindings-Provider.exe` 和 `openvr_api.dll`。

## 模型权重

实时程序读取 `checkpoints/<模型名>/base_model.pth` 与同目录的 `manifest.json`（缺少 manifest 或帧率/窗口/布局不符会直接报错）。当前可用：

| 目录 | 说明 |
|---|---|
| `checkpoints/pnp5_60a_s42_ftr3/` | 默认，SparseIMU 主基线 |
| `checkpoints/pnp5_60a_sc_ftr3/` | 恒等锚定版（`manifest.anchored=true`，自动启用锚定） |

两个文件各约 22 MB，在训练服务器上由 `scripts/convert_sparseimu_checkpoint.py` 生成；拷到真机目录时要整个子目录（含 `manifest.json`）一起拷。旧的 `checkpoints/no_head_5imu_surface/` 与 `results/ours_multi_finetune/` 已废弃（30 fps、旧位置），不要再作为 `--checkpoint` 使用。

## SlimeVR 绑定

在 SlimeVR GUI 的 Trackers / Body assignment 里给 5 个 tracker 分别指定身体部位，**只绑这 5 个**：

| 传感器佩戴位置 | SlimeVR 身体部位（界面名） | 协议枚举 |
|---|---|---|
| 左前臂（近腕，背侧） | Left lower arm | `LEFT_LOWER_ARM` |
| 右前臂（近腕，背侧） | Right lower arm | `RIGHT_LOWER_ARM` |
| 左小腿（膝下，前内侧） | **Left ankle**（界面叫 ankle，对应枚举 LOWER_LEG，不是 Left foot） | `LEFT_LOWER_LEG` |
| 右小腿（膝下，前内侧） | **Right ankle**（同上） | `RIGHT_LOWER_LEG` |
| 骨盆（后侧骶骨） | Hip | `HIP`（`WAIST` 也接受，不要同时绑两个） |

- 不要绑 Left/Right foot（脚）、Left/Right thigh（大腿，枚举 UPPER_LEG）、Upper arm（上臂）、Chest、Head；这些部位的 tracker 会被忽略，但五个必需部位缺任何一个或重复绑定都会导致程序一直等待/报歧义。
- 佩戴位置图见 `01_项目目标与当前状态.md`（`docs/images/sensor_placement_pnp5.png`）。
- 绑定后按下一节做 Full Reset 和 Mounting Calibration，再启动 Python。绑定只是路由，模型实际使用的是传感器在身体上的物理位置，所以位置必须和图一致。

## SlimeVR Mounting Calibration（朝向校准）

SlimeVR 里没有"小腿"这个独立部位，`Left/Right ankle`（`LOWER_LEG`）是最接近的槽位。我们的程序只读取每个 tracker 经 SlimeVR 校准后的旋转（`rotationReferenceAdjusted`）和加速度，不使用 SlimeVR 的骨架位置，所以只要传感器牢固贴在小腿骨段上，绑 ankle 只是路由标签；但**这一点没有在真机上验证过**，请用下面的检查确认。

按 SlimeVR 自带向导（`Mounting Calibration`，界面标注 Recommended）做 **Automatic mounting**，它会估计每个 tracker 绕肢体轴的朝向，适合我们这种不是正前/正侧的佩戴（小腿传感器在前内侧，约偏离正内侧 36°）：

1. 点 **Full Reset**，站直，手臂放在身体两侧，看向前方，保持到 3 秒倒计时结束。
2. 摆"滑雪姿势"：双腿弯曲，上身前倾，手臂弯曲。点 **Mounting calibration**，保持 3 秒。
3. 不需要做 Feet Calibration（我们没有脚部 tracker）。
4. 手臂的 Reset 模式（Settings → Skeleton → Arm tracking → reset mode）保持默认 **Back**（上臂向后、前臂向前，正好对应第 2 步的滑雪姿势手臂）。程序里前臂的固定 ±90° z 旋转（`calibration.py`）就是按 SlimeVR 的这一约定验证过的，不要改成 T-pose 模式，除非同时重新验证。
5. 手动 Manual mounting 只能选方向，不如自动精确；仅在自动校准反复失败时再用。

校准后用站立检查确认（只检查骨盆和小腿，前臂在手臂自然下垂时约 90°）：

```powershell
python -m production.run --model pnp5_60a_s42_ftr3 --record recordings\stand.jsonl   # 站直不动约 5 秒后 Ctrl+C
python scripts\check_standing_orientation.py recordings\stand.jsonl
```

骨盆和左右小腿应接近 0°；若出现约 90° 或 180°，说明该 tracker 的 mounting、Full Reset 或绑定不对，重新做 Full Reset + Mounting calibration。如果在 SlimeVR 里启用了骨骼约束类选项（源码里有 `constraintFix`，会修改 tracker 旋转），首次验证请关闭。

## 佩戴与启动顺序

1. 按 `01_项目目标与当前状态.md` 的位置表佩戴：前臂近腕背侧、小腿膝下前内侧、骨盆后侧骶骨。
2. 启动本地编译的 SlimeVR。
3. 按上一节完成 Full Reset 与 Mounting Calibration。
4. 绑定 Left/Right lower arm、Left/Right ankle（枚举 `LEFT/RIGHT_LOWER_LEG`）、Hip（`HIP`）（`WAIST` 也被接受，但不要同时绑定两者）。
5. 启动 Python，再打开 Unity AvatarScene。
6. 浏览器打开 `http://127.0.0.1:8765/`。

## 当前启动命令

```powershell
python -m production.run `
  --model pnp5_60a_s42_ftr3 `
  --acceleration-source server `
  --web
```

常用选项：`--model pnp5_60a_sc_ftr3` 使用恒等锚定版；`--infer-every 1` 以 60 poses/s 推理（单窗口前向在服务器 CPU 单线程约 15 ms，真机请先用 `--record` 看 `inferenceEnd - inferenceStart` 再决定）；`--output-fps 30/20/60` 是 `--infer-every` 的另一种写法（必须整除 60）；`--anchor auto|on|off`（`auto` 跟随 manifest，与 manifest 矛盾会报错）。`--include-contact` 已无效（新基线没有接触头）。

当前不再执行 Python 150 帧 heading 拟合；`--calibration-frames` 仅为旧命令兼容保留。Unity 基线先关闭 Tracker Anchors、Foot Grounding、Joint Limits、Knee Guard 和 Ground Guide。
