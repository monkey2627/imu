# 侧桥路由修正与死虫腿部规则调整（2026-11-19）

## 侧桥

- Unity 发出的动作名是 `sidebridge_left` / `sidebridge_right`，从不发 `sidebridge`。此前这两个名字路由到 `waist_streamposer_ours_all10`，新的 `waist_imudino_stream_sidebridge_v3_rehabv5_20261118` 实际上没有被用到。现已在 `production/model_backends.py` 的 `ACTION_RUNTIME_MODELS` 中改为指向 v3 模型。
- `production/bridge_contact.py` 的 `BRIDGE_MODELS` 中去掉了侧桥模型。原因：侧桥自己的校准不会生成平躺校准，但如果同一次运行里先做过臀桥，残留的平躺腰部修正和躯干偏差会被套到侧卧上。臀桥接触规则本身只在仰卧时生效。
- 同时还原了 `bridge_contact.py` 文档字符串中被错误编码写坏的"臀桥"二字，并去掉了文件头的 BOM。
- **尚未用真实数据验证**：recordings 中没有侧桥真实录制，需要按新流程补录。

## 死虫

- 生产代码改用对比视频中的方案 ③：`waist_imudino_stream_deadbug_rehabv5_std_20261118` 不再启用 `deadbug_legs`（根据小腿位移估计大腿）。实现方式是在 `production/frame_chain.py` 新增 `DEADBUG_LEG_ESTIMATOR_MODELS`，`LegChain.enabled_for` 改为按这个集合判断。旧的死虫模型仍按原逻辑启用。
- 原因：这个模型自己能预测死虫的腿。在真实录制 045157 / 063451 上，`deadbug_legs` 会把桌面式的膝屈和髋屈压到约 140°（膝盖贴到胸口），伸腿阶段也会让腿蜷起。
- 方案 ③ 相对网络原始输出（方案 ①）只做三处改动：
  1. 前臂和小腿锚定为校准后的 IMU 实测值，差异约 10–14°。
  2. 伸臂先验：手臂伸出或朝天时，把上臂对齐前臂，使肘伸直，差异约 11–17°。
  3. 起始姿态约束：开头几秒固定桌面式，肢体开始动后逐步解除。
  躯干、颈和头不做任何改动。
- 已验证：默认 `--deadbug-legs auto` 的离线回放结果与方案 ③ 逐帧一致。

### 背部贴地约束（`production/deadbug_floor.py`）

问题：死虫时背部应该贴在垫子上。实测躯干本身是平的（仰卧帧俯仰中位约 0°），但伸腿时腿会低于背部：脚跟/小腿在 31–45% 的帧里低于背部，最多低 11–26 cm；045157 里头在 47% 的帧里低于背部，最多低 9 cm（头后仰）。渲染时按最低点落地，背就被顶起来；Unity 里地面高度固定，结果就是腿和头穿进地面。

做法：只在仰卧时生效（脊柱接近水平、胸口朝上），以背部（骨盆和 spine1–3 网格区域）的最低点作为地面。
- 腿低于地面时，绕髋关节抬大腿，增加屈髋；小腿保持实测朝向，只随膝盖平移。抬到腿的最低点刚好到达地面为止。
- 头低于地面时，让头颈前收，直到后脑勺落在地面上。
- 只往上抬，不往下压。修正角度做低通滤波，并限制变化速率（每秒最多 240°），仰卧判定权重以 4/s 渐变。
- 判断"低于地面"用的是 SMPL 模板网格：每个顶点刚性跟随其主导骨骼，降采样 1/3。每帧耗时约 0.5 ms。

结果（仰卧帧）：

| 部位低于背部的帧占比 | 045157 前→后 | 063451 前→后 |
|---|---|---|
| 膝盖 / 大腿 | 23% → 0% | 40% → 1% |
| 脚跟 / 脚 | 31% → 9%（最多 −11 → −1.4 cm） | 45% → 17%（最多 −26 → −2.8 cm） |
| 头 | 47% → 3% | 0% → 0% |

髋屈中位数基本不变，说明只在腿往下沉时才抬，其他时候不改动姿势。若小腿实测朝向向下倾斜（例如 063451 在 9.4 s 时右小腿向下约 30°），背贴地时腿只能是弯的，此时输出屈膝约 70°。这和传感器读数一致；网络给出的"直腿伸到地板以下"在物理上不可能。

测试：`python -m analysis.deadbug_floor_test`。
