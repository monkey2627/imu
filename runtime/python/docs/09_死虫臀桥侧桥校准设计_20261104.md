# 死虫、臀桥、侧桥的校准设计（2026-11-04）

状态：**已实现（2026-11-04），已通过合成数据验证，尚未做真人实测**。思路与鸟狗校准一致：校准动作尽量就是该游戏动作本身或它的准备姿势，不要求用户起身站立。实现与验证结果见第 7 节。

## 1. 设计原则（来自鸟狗的经验）

1. **校准的核心是前臂和小腿的世界航向（1 个自由度）。** 实测这类误差表现为世界航向偏移：同一次佩戴中，前平举、手背朝外、侧平举三种姿势下前臂方位的偏差几乎相同（左约 +20°，右约 +33°），而且在 27 秒内基本不变。个别佩戴会出现超过 100° 的偏差（右前臂 +113~+128°）。只校准航向时，掌心朝向（绕骨骼轴的扭转）不需要已知。
2. **只有接近水平的骨骼才能看出航向。** 骨骼俯仰超过 ±45° 时跳过（代码中的 `MAX_LEVEL_ELEVATION_DEG`）；竖直的骨骼只能约束倾斜，看不出航向。
3. **目标方向用躯干坐标表达，不用世界坐标。** 用户躺下、侧卧后，"前方"已经不是水平朝前。统一用腰部传感器定义两个轴：
   - 头向轴 **h**：腰骨骼的 +y（脊柱方向）在水平面上的投影；
   - 胸向轴 **c**：腰骨骼的 +z（胸口法向）。
   
   注意：鸟狗现有代码用 `_best_yaw(waist) @ z` 作为前方。俯卧时它恰好等于头向，**仰卧时却指向脚**。新动作必须改用 h，不能直接复用。
4. **采样窗口取"该步骤内最近一段水平且静止的 0.5 秒"**，不要只取倒计时结束那一刻。鸟狗中已发现用户常在倒计时结束前就放下手或腿。
5. **航向不设上限**，靠"骨骼接近水平"和"静止"两个条件把关。能有第二个姿势时，用它做交叉检验，见各动作的"检验步骤"。
6. **腰部只做必要的修正。** 躺平时骨盆前后倾因人而异（教练录制中，骨盆到胸廓的连线与水平面成 9–24°），所以仰卧时**只修正左右侧倾（roll），不修正前后倾（pitch）**。腰的航向本身就是参考，不修正。

## 2. 教练录制中三个动作的姿势（依据）

数据：Ours 教练录制 `4_臀桥`、`5_侧桥`、`7_死虫`，即游戏所用录制的同一批源数据。脚本：`analysis/calibration/coach_pose_geometry.py`。下表中的"与头向夹角"：0° 表示指向头，180° 表示指向脚。

| 动作与阶段 | 前臂 | 小腿 | 能看出航向的骨骼 |
|---|---|---|---|
| 死虫 准备（仰卧屈膝，双臂放体侧） | 俯仰 −2~+4°，与头向夹角 150–163°（沿身体指向脚） | 俯仰约 −70°（屈膝踩地） | 双前臂 |
| 死虫 桌面式起始姿势 | 俯仰 +80~+88°（竖直朝天） | 俯仰 −1~+7°，与头向夹角 155–162°（水平指向脚） | 双小腿 |
| 死虫 伸展（对侧手脚） | 伸出的手：俯仰 +12~+28°，与头向夹角 34–52°（指向头的上方） | 伸出的腿：小腿仍近水平，大腿从 +80° 降到 +30~+47° | 伸出的前臂（用于检验） |
| 臀桥 起始与顶端 | 俯仰 −5~+10°，与头向夹角 157–174°（平放体侧指向脚），全程不变 | 俯仰 −66~−78°（很陡），全程不变 | 只有双前臂 |
| 左侧桥 起始（左肘支撑，屈膝） | 左（支撑）：俯仰 −10~−16°，与头向夹角 93–110°（垂直于身体、指向胸前）；右：俯仰 −18~−27°，沿身体指向脚 | 俯仰 −12~+3°，但左右小腿相差约 40°，方向不固定 | 双前臂；小腿不可靠 |

结论：
- **臀桥、侧桥的游戏动作本身无法校准小腿航向**：臀桥的小腿太陡，侧桥的小腿方向不固定。所以需要一个"仰卧伸腿"的准备步骤。
- **死虫**：前臂在准备姿势中校准，小腿在桌面式姿势中校准，都是游戏原本就有的姿势。

## 3. 各动作的校准流程

每一步：屏幕提示、倒计时、在该步骤内取最近一段水平且静止的 0.5 秒、解算、显示结果。时长是建议值。

### 3.1 死虫（全部用游戏本身的姿势）

| 步骤 | 提示语 | 时长 | 解算内容 |
|---|---|---|---|
| D1 仰卧准备 | "仰卧，屈膝脚踩地，双臂伸直放在身体两侧，掌心向下，保持不动。" | 6 s | 双前臂航向：目标 = −h（指向脚）；腰：只修正左右侧倾 |
| D2 桌面式 | "双腿抬起，大腿垂直、小腿与地面平行；双臂伸直指向天花板，保持不动。" | 8 s | 双小腿航向：目标 = −h，并使两小腿平行；双前臂：只检查是否竖直（倾斜误差 &gt; 20° 时提示），不修正 |
| D3 检验（可选） | "右手向头顶方向伸展、左腿伸直，保持 3 秒，再换另一侧。" | 每侧 6 s | 不修正，只报告：伸出的前臂与 h 的方位差。超过 25° 时提示"手臂航向可疑，请重新校准" |

为什么这样设计：D1 和 D2 是教练录制里实际出现的两个姿势，用户本来就要经过它们。双臂朝天时看不出前臂航向，所以前臂放在 D1 做。D3 的伸展方向依赖用户把手伸到什么位置，误差较大，所以只用于检验。

### 3.2 臀桥（增加一个"仰卧伸腿"准备步骤）

| 步骤 | 提示语 | 时长 | 解算内容 |
|---|---|---|---|
| H1 仰卧伸腿 | "仰卧，双腿伸直并拢，双臂伸直放在身体两侧，掌心向下，保持不动。" | 6 s | 双前臂航向：目标 = −h；双小腿航向：目标 = −h，并使两小腿平行；腰：只修正左右侧倾 |
| H2 起始姿势 | "屈膝，双脚踩地与髋同宽，双臂保持在身体两侧，保持不动。" | 6 s | 双前臂航向复核：仍应约为 −h，与 H1 相差 &gt; 15° 时提示；小腿太陡，不解算 |

为什么这样设计：臀桥的小腿全程俯仰在 −66° 到 −78° 之间，航向看不出来。但模型的输入是完整朝向，航向错了仍会造成影响，所以要在小腿水平的时候先校准。H1 是躺下后、屈膝之前的自然姿势，不需要起身。前臂在臀桥中一直平放在体侧，所以 H2 可以顺便复核一次。

### 3.3 左侧桥（仰卧伸腿 + 侧卧起始姿势）

| 步骤 | 提示语 | 时长 | 解算内容 |
|---|---|---|---|
| S1 仰卧伸腿 | 同 H1 | 6 s | 同 H1：双前臂、双小腿航向，腰的左右侧倾 |
| S2 侧卧起始姿势 | "向左侧卧，左前臂撑地、肘在肩正下方、前臂指向身体前方；右手放在右侧大腿上；屈膝，髋部先不抬起，保持不动。" | 8 s | 不修正，只检验：左前臂应与 c 平行，右前臂应约为 −h，各自方位差超过 25° 时提示 |

为什么这样设计：侧卧时，左右小腿方向相差约 40°，而且因人而异，不能作为校准基准，所以小腿在 S1 中校准。S2 的两条前臂方向明确，但支撑前臂的方向取决于用户把手放在哪里，所以只用于检验。若 S1 与 S2 结果一致，可信度高；若不一致，说明某一步的姿势没做到位。

注意：从仰卧翻成侧卧时，腰部传感器跟着转了 90°，h 和 c 也随之变化。S2 要使用 S2 窗口中的 h 和 c，不能沿用 S1 的。

## 4. 实现方案（待实现）

### 4.1 Python 端（`pose_calibration.py`）

把"已知姿势保持"做成一个通用解算器，以表格方式定义每个姿势，不再为每个游戏单独写一套代码：

```python
KNOWN_HOLDS = {
    # 姿势 ID: {传感器: (目标方向, 用途)}；目标方向在躯干坐标中表达
    "supine_arms_side":     {"lw": ("-h", "solve"), "rw": ("-h", "solve"), "waist": ("roll", "solve")},
    "supine_legs_straight": {"lw": ("-h", "solve"), "rw": ("-h", "solve"),
                             "ls": ("-h", "solve"), "rs": ("-h", "solve"), "waist": ("roll", "solve")},
    "deadbug_tabletop":     {"ls": ("-h", "solve"), "rs": ("-h", "solve"),
                             "lw": ("up", "check"), "rw": ("up", "check")},
    "deadbug_reach_left":   {"lw": ("+h", "check")},
    "deadbug_reach_right":  {"rw": ("+h", "check")},
    "hipthrust_start":      {"lw": ("-h", "check"), "rw": ("-h", "check")},
    "sidebridge_left_start":{"lw": ("+c", "check"), "rw": ("-h", "check")},
}
```

- `solve`：前臂、小腿只求左乘世界航向（同 `_solve_arms_forward`，但目标方向改用 h、c）；腰的 `roll` 只修正绕 h 轴的侧倾。
- `check`：不改修正量，只报告误差。超过阈值时，返回提示给 Unity 显示。
- 采样窗口：沿用 `_latest_level_hold`，在该步骤的时长内找最近一段水平且静止的 0.5 秒。
- 新增命令：`{"command":"poseHoldCalibrate","pose":"<姿势 ID>"}`。离线回放 `offline_compare.calibrated_orientations` 时同样要支持这条命令，保证离线复现与实时一致。

### 4.2 Unity 端（`MobilePoseCalibrationController.cs`）

- `StepKind` 增加 `PoseHold`，`Step` 增加字段 `poseId`；步骤结束时发送 `poseHoldCalibrate`。
- `CreateDefaultSteps` 按场景名生成上面三套默认流程：`deadbug` 对应 D1–D3，`hipthrust` 对应 H1–H2，`sidebridge` 对应 S1–S2。
- 结果提示沿用现有的 `resultUntil` 机制：返回消息以 `pose hold calibration:` 开头。
- 不修改游戏逻辑脚本，只改校准控制器。

### 4.3 SlimeVR 重置时机（风险）

现在 Unity 在 `Standing` 和 `BirdDogBase` 步骤会发送 `yawReset`。SlimeVR 的重置是按站立姿势设计的，在四点跪姿、仰卧时做重置，结果可能不正确。这一点**还没验证**。新流程中，躺下的步骤不发送 `yawReset`，SlimeVR 重置统一在站立时完成（游戏开始前或第一组之前）。鸟狗当前的做法也应复查。

## 5. 验证计划

1. 每个动作录一段完整的校准加游戏（校准过程会自动保存为 `recordings/calibration_*.jsonl`）。
2. 离线检查：
   - 校准后，前臂、小腿在各个检验姿势下与目标方向的方位差（D3、H2、S2），目标 &lt; 15°；
   - 用另一次站立前平举的录制做交叉验证（与鸟狗相同的方法）：校准后前平举时前臂方位应接近 0°；
   - 模型输出：校准前后关键姿势的上臂与小腿方向对比。
3. 失败时的处理：若某个检验步骤持续报错，先确认用户姿势是否到位（看录制的逐帧方向，脚本 `analysis/calibration/bird_dog_calib_timeline.py` 可以改用于这里），再调整目标方向或阈值。

## 6. 尚未解决、校准也解决不了的问题

- **前臂扭转（掌心朝向）**：这些流程都不校准扭转。真实传感器在翻转手掌时只测到约 30–50% 的扭转，属于模型与数据的问题，见 `docs/06` 和 2026-11-04 对训练数据的统计。
- **大腿角度**：死虫伸腿时，小腿仍接近水平，大腿从约 80° 降到 30–47°。这和鸟狗的伸腿一样，小腿传感器在原理上测不出大腿角度，校准无法解决（详见 `analysis/reports/leg_observability_report.html`）。死虫的伸腿评价同样需要额外的传感信息，例如气压计。
- **臀桥的骨盆高度**：只有腰部朝向，没有高度信息。目前评分依赖模型推断的姿态。

## 7. 实现与验证（2026-11-04）

### 7.1 改动位置

| 文件 | 内容 |

| `production/offline_compare.py` | 离线回放支持 `poseHoldCalibrate` 事件 |
| `SpineRecovery_V2/Assets/Scripts/MobilePoseCalibrationController.cs` | 新步骤类型 `PoseHold`（枚举末尾追加，不改变已有序列化值）和 `poseId` 字段；按场景名生成三套默认流程；结果含 `CHECK FAILED` 时提示重新校准 |

实际流程与第 3 节一致，有一处补充：死虫在两次伸展之间、以及最后，各插入一个纯提示步骤（"回到双臂朝天……"、"回到起始姿势……"）。这三个场景都不发送 SlimeVR `yawReset`。Unity 编译检查（csc，按 `Assembly-CSharp.csproj` 生成 rsp）：0 个错误、0 个警告。

### 7.2 合成验证（`analysis/calibration/pose_hold_synthetic.py`）

用真实的 SMPL 骨骼朝向构造各保持姿势，注入以下误差：前臂、小腿的世界航向误差（左前臂 +25°、右前臂 −115°、左小腿 +30°、右小腿 −20°），腰绕脊柱 10° 的侧倾安装误差，以及每个传感器约 3° 的随机安装倾斜。身体朝向设为任意的 37°。然后按三套流程逐步回放，在**未参与校准的站立姿势**下测量误差：

| 流程 | 解算结果 | 站立前平举 / 侧平举时前臂指向误差 | 站立时腰的误差 |
|---|---|---|---|
| 死虫 | lw −17°，rw +116°，ls −27°，rs +21°，腰侧倾 −10°；全部检验通过 | 0.8° / 0.6° | 0.2° |
| 臀桥 | 同上（在一步内完成）；检验 0° | 0.8° / 0.6° | 0.2° |
| 左侧桥 | 同上；侧卧检验 0° | 0.8° / 0.6° | 0.2° |
| 死虫，**用户错误**：第一步双臂外展 30° | 前臂航向多修了 30° | 30° / 30° | 0.2° |

- 前臂残差小于 1°。右前臂即使有 −115° 的大误差，也能完整恢复。
- 小腿航向的修正量与注入值相差 1–3°，来自注入的随机安装倾斜。小腿在站立时的指向残差为 6–10°，就是这部分安装倾斜：躺姿流程按设计只校准航向，不校准倾斜。
- 用户错误那一例：死虫的伸展检验报出 `lw +31° from +h CHECK FAILED`、`rw −30° … CHECK FAILED`，屏幕会提示重新校准。臀桥和侧桥只有一个解算步骤和一个检验步骤；如果用户在两步中都犯同样的错误，检验会查不出来。
