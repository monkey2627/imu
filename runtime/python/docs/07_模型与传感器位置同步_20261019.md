# 模型与传感器位置同步（2026-10-19）

realUse 的 Python 预测部分已从旧模型/旧位置同步到 SparseIMU 现行基线（`pnp5_60a`）。本文是变更说明、验证记录与回滚方法。

## 旧 → 新

| 项 | 旧 | 新 |
|---|---|---|
| 权重 | `checkpoints/no_head_5imu_surface/<layout>/1/base_model.pth`、`results/ours_multi_finetune/...` | `checkpoints/pnp5_60a_s42_ftr3/`（默认）、`checkpoints/pnp5_60a_sc_ftr3/`（恒等锚定），各含 `base_model.pth` + `manifest.json` |
| 帧率 / 窗口 | 30 fps，窗口 45，输出下标 40，滞后 133 ms | 60 fps，窗口 91（80 过去 + 10 未来），输出下标 80，滞后 167 ms |
| 推理节拍 | 每个输出帧推入一次窗口 | 窗口固定 60 Hz 推进，默认每 2 帧推理（30 poses/s），`--infer-every` 可调 |
| 传感器位置 | 前臂外侧 75%、小腿外侧近踝（实际用脚踝）、腰前侧 spine1 | 前臂背侧 85–87%、小腿膝下前内侧、骨盆后侧骶骨 |
| 骨盆朝向 | spine1（关节 3） | 骨盆（关节 0） |
| 布局 | 6 种 | 1 种：`pnp5_forearm_shank_pelvis` |
| 绑定 | `LEFT/RIGHT_LOWER_ARM`、`LEFT/RIGHT_FOOT`（文档）或 LOWER_LEG（代码）、`WAIST` | Left/Right lower arm、Left/Right ankle（枚举 `LEFT/RIGHT_LOWER_LEG`，GUI 里叫 ankle）、`HIP`（`WAIST` 也接受） |
| 足接触 | 旧接触头 | 移除（新基线没有） |

注意：旧文档 03 写的是绑定 `LEFT_FOOT/RIGHT_FOOT`，而 `layout.py` 把 FOOT 映射成 `lf/rf`、LOWER_LEG 才是 `ls/rs`。新代码只认 LOWER_LEG；如果小腿传感器仍戴在脚踝，需要移到膝下，并在 SlimeVR 里改绑 LOWER_LEG。

## 恒等锚定（`pnp5_60a_sc_ftr3`）与默认模型

恒等锚定是在基线上改的：同一 Joints→Poser，Poser 对被传感骨（骨盆、双小腿、双前臂）输出 `R_测量 @ R(δ)`。DIP 角度更好（8.43° vs 9.25°），TotalCapture 更差（官方标定 SIP +0.5°、Ang +0.6°），对 SlimeVR 标定偏差更敏感。默认用主基线 `pnp5_60a_s42_ftr3`；锚定版由 `--model pnp5_60a_sc_ftr3` 选择，`manifest.anchored=true` 时自动启用，`--anchor on/off` 与 manifest 矛盾会报错。真机上哪个更好尚未验证。

## 验证结果（2026-10-19，服务器）

- **与 SparseIMU 基线逐帧一致**：DIP 测试集前 2 条序列 × 前 1200 帧，每条 1110 个完整窗口的帧，realUse 封装 vs `evaluate_standard.online_predict`（`MOBILEPOSER_FPS=60`）：主基线 max|diff| = 5.4e-7，恒等锚定 5.1e-7（容差 1e-4）。
- **延迟**：一次 91 帧窗口前向，服务器 CPU 单线程均值 14.7 ms（p95 15.3 ms）。30 poses/s 的预算 33 ms 足够；60 poses/s 的预算 16.7 ms 与前向耗时接近，真机需实测。
- **历史验证记录**：当时完成了契约、窗口、布局、转换、录制回放和假 SolarXR 端到端检查；测试源码已在 2026-11-11 按“以实际使用为准”清理，当前以真实 SlimeVR → Python → Unity 链路验证为准。
