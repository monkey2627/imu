# 交接说明（2026-11-10）

本文记录当前代码位置、主要工作线结论、验证状态和待确认事项。先读本篇，再按需打开对应的专题文档。

## 当前入口

项目主链路为 SlimeVR → SolarXR → Python 实时推理 → Unity / Web 查看器。Python 入口是 `runtime/python/production.run`；Unity 场景为 `runtime/unity/SpineRecovery_V2/Assets/Scenes/AvatarScene.unity`。五个传感器按当前 waist-surface 布局绑定前臂、小腿和腰部，详细位置及 SlimeVR 绑定见 `docs/01_项目目标与当前状态.md`、`docs/03_安装构建与启动.md`。

Windows 开发环境使用 `mobileposer` conda 环境。当前代码的默认模型 ID 是 `waist_mobileposer_amass`：

```powershell
conda activate mobileposer
python -m production.run --model waist_mobileposer_amass --web
```

实时模型索引在 `production/model_backends.py`，16 个 waist-surface 权重统一位于工作区 `local_models/checkpoints/<model_id>/`。老的 SparseIMU PNP 权重仍在 Python runtime 的 `checkpoints/pnp5_60a_s42_ftr3/` 和 `checkpoints/pnp5_60a_sc_ftr3/`，可显式通过 `--model` 选择。

**需要先确认的文档漂移：** `production/run.py` 和根目录 `README.md` 使用 waist-surface 模型作为默认启动路径；`docs/01、03、06、07、08` 的部分段落仍把 `pnp5_60a_s42_ftr3` 写作当前默认模型。启动前以代码的 `DEFAULT_RUNTIME_MODEL`、`model_backends.py` 和权重实际位置为准；不要据这些旧段落更换模型或传感器布局。后续应统一这些文档，但本次整理没有重写模型说明。

## 工作线结论

| 工作线 | 当前结论与状态 | 入口 / 详述 |
|---|---|---|
| 实时五 IMU 主线 | SolarXR 输入经校准和特征组装后送入实时模型，再广播给 Unity；支持录制、回放和 Web 可视化。新布局与新权重的真机域差异仍需实际佩戴验证。 | `production/run.py`；`docs/02`、`docs/03`、`docs/04` |
| 前臂航向与大臂先验 | 前平举偏差主要可由前臂航向误差解释；`arm_prior.py` 是模型输出后处理，不替代传感器校准。 | `analysis/arms/arm_prior_eval.py`；`docs/05` |
| 鸟狗及躺姿校准 | 鸟狗航向校准已有脚本与合成验证。死虫、臀桥、侧桥的 pose-hold 校准已实现并通过合成验证，尚无真人实测。 | `production/pose_calibration.py`；`docs/09`；`analysis/calibration/` |
| 腿部可观测性 | 只有小腿传感器时，跪地与伸直抬腿可能具有近似小腿朝向，模型不能可靠区分；报告建议需增加大腿 IMU 或气压等信息。 | `analysis/reports/leg_observability_report.html`；`analysis/legs/` |
| 加速度积分 | 桌面平推/抬高测试可得到大致位移；佩戴状态下手臂动作仍不可靠，原因未查明，用户已决定停止该测试线。 | `analysis/acceleration/` |
| PosAcc 实验 | 未通过预先设定标准；教练合成数据上的提升在加速度清零后仍存在，用户录制未能区分抬腿与跪地，不建议实际使用。 | `checkpoints/realuse_waist_surface_20261030/posacc_s42_amass/README.md` |
| Deadbug 微调 | 同一段录制的 FBX-to-SMPL 伪标签同时用于微调和评估，属于序列过拟合，不是留出测试或独立真值。 | 根目录 `README.md`；服务器工作区 `README.md` |
